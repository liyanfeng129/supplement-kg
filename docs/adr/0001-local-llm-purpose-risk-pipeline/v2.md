# 1. Local LLM extraction of DSLD purpose/risk

- **Version:** 2 (2026-10-07). [v1](v1.md) is the 2026-09-11 decision as first
  built, under `engine/pipeline/`; that code is deleted.
- **Status:** Accepted
- **Where the code lives:** [ADR 0002](../0002-engine-architecture/) decides the
  layers. This ADR decides what the extraction does, not which file does it.

## Context

`DSP.csv` has `Purpose` and `Risk` populated only where a row carries an
LNHPD `NHP_ID`. All 92,442 DSLD-only rows are empty by construction: a
regulatory artefact, not a data bug. US supplement labels have no purpose
field, so the text exists only inside `statements[]` as free prose.

`docs/dsld-purpose-risk-findings.md` established that the information is
recoverable, that a statement-type→column mapping cannot get at it, and that
every candidate skip filter leaks. So: scan every label, one passage per
label, LLM extraction.

There is no `ANTHROPIC_API_KEY` on this machine, so extraction runs on a local
model.

## Decision

### 1. One local model, GPU-only

`Qwen3.8-27B`, the Unsloth `UD-Q4_K_XL` GGUF (`general.file_type = 15`,
Q4_K_M; v1 §5 misread it as Q6_K). It is hosted by `llama-server`, which is
`engine/models/qwen_model.py`'s private business (ADR 0002 §3). Tuned settings
and the measurements behind them are in
[spec 0001](../../specs/0001-qwen-model-controller.md).

**There is no CPU path.** ggml's CUDA backend fails to initialise on
pinned-memory allocation in this environment and falls back to CPU silently,
at ~100x the cost, with correct-looking output. `GGML_CUDA_NO_PINNED=1` makes
CUDA init succeed, and the model refuses to run on a card without room, a load
that did not reach the GPU, or a model that answers garbage.

### 2. Results: JSONL run directories, resumed by absence

A run is a directory of JSONL rows plus a manifest, laid out per
[ADR 0003](../0003-repositories-one-folder-per-data-source/). A label is done
when its id has a complete row; resume is the run's ids without one. A torn
last line counts as not done.

The manifest holds `config_hash`, which covers everything that changes an
answer: the prompt (system text, stop sequences, output budget, check names),
the model, its sampling settings and the attempt budget. Speed settings are
left out. Resuming with a different `config_hash` or `passages_sha` is
refused; the fix is a new run.

### 3. A prompt is a folder

`engine/repositories/prompts/<id>/` holds `prompt.md`, the checks that accept
or reject a generation, the parser, stop sequences and the output budget. One
working copy per prompt; the run manifest records the hash that covers it.

### 4. Every label gets a row, with a status

`ok`, `failed_checks`, `too_long` or `error`. A failed row keeps the raw text.
The controller retries a generation that fails its checks, up to
`max_attempts`. Failures never stop a run; past a failure-rate threshold a
person is notified, once. Only `ModelUnavailable` stops a run.

## What v1 decided that no longer holds

| v1 | now |
|---|---|
| §1 three drivers (`local`, `api`, `agent`) sharing a row contract | one local model behind a controller (ADR 0002) |
| §2 `load_runs()` glob into pandas | deleted; cross-run analysis belongs to whatever does the analysis |
| §3 hash over `schema_sha`, `renderer_version` | hash over prompt, model, sampling, attempts (§2 above); passages are pinned by `passages_sha` |
| §6 GBNF grammar from the JSON schema | a line output format and checks; the grammar cost 4.2x decode speed |
| §7 in-process `llama-cpp-python`, `smoke` command | `llama-server` inside the model; the model checks itself in `ready()` |
| §8 no inline retries | the controller retries up to `max_attempts` |
| §10 workers, appender thread, poison guard, stdout timer | the controller keeps `in_flight` prompts queued, retries, and reports progress; the `Sink` appends |
| §11 scorer against the gold set | **no scorer exists in the current code.** v1's `score.py` and its tests are in git history (last present at `f8c73e3`) |
| §12 `engine/pipeline/` module layout | ADR 0002 |
