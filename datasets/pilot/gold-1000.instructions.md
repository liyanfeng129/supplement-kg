# Task: extract Purpose and Risk from DSLD supplement labels

You are building rows for a reference ("gold") set. Work entirely offline:
do NOT call any API, do NOT use WebFetch/WebSearch, do NOT write code that
calls a model. YOU read each passage and YOU write the extraction yourself.

## Input
Your shard file is JSONL, one object per line: {"dsld_id", "name", "passage"}.
Read it with the Read tool (or `cat`). Process EVERY line. Do not skip any.

## Output
Write ONE output file, JSONL, one object per input line, SAME ORDER:

{"dsld_id": <int>, "idisk_id": null, "name": "<name>", "purpose": [ENTRY,...],
 "risk": [ENTRY,...], "purpose_confidence": 0-5, "risk_confidence": 0-5,
 "model": "claude-opus-5-subagent", "extracted_at": "<UTC ISO8601>"}

ENTRY = {"text": "<normalised claim>", "evidence": "<verbatim span>"}

## The one hard rule
`evidence` MUST be copied character-for-character from that label's `passage`.
It is checked mechanically with a verbatim substring test after you finish;
any entry that fails is discarded and the shard is re-run. Never paraphrase,
never fix a typo, never join text across lines inside one evidence string.
Copy the substring exactly as it appears.

Write the file with a heredoc or a small Python script that json.dumps each
row -- do not hand-write JSON escaping.

## Extraction rules (authoritative; follow exactly)
The rules below are the project's frozen prompt. The first 100 labels of this
gold set were labelled against this exact text, so follow it literally rather
than substituting your own judgement about what a purpose or risk is.

---
You extract structured attributes from US dietary supplement label text.

You extract structured attributes from US dietary supplement label text.

You are given the text printed on one product's label. Recover two fields:

- purpose: what the product is claimed to do for the person taking it -- the
  benefit or intended use ("supports restful sleep", "helps maintain healthy
  joints"). This is the product's structure/function claim.
- risk: cautions, warnings, contraindications, and interactions -- who should
  not take it and what to watch for.

Rules:
- Use ONLY what the label says. Never add pharmacological knowledge of your
  own: if a label for a melatonin product never states a purpose, the purpose
  is null, even though you know what melatonin is for. This corpus is used to
  build a knowledge base, so an inferred claim is worse than a missing one.
- Quote or lightly normalise the label's own wording; do not embellish.
- Purpose statements are often buried in generic "General Statements" blocks
  alongside boilerplate ("Made in the USA", "ACTUAL SIZE"). Ignore the
  boilerplate and pick out the benefit claim.
- The FDA disclaimer ("This statement has not been evaluated by the FDA...")
  is not a purpose. Directions/dosage alone are not a purpose.
- "KEEP OUT OF REACH OF CHILDREN" alone is boilerplate, not a risk; include it
  only if no other risk text exists.
- A risk is about the product's effect on the person taking it -- who should
  not take it, what to watch for, what it interacts with. Statements about the
  container, its packaging, its seal or its physical condition are not risks,
  however they are phrased and even when phrased as an instruction not to use
  the product. They describe the package, not the supplement, and they would
  be equally true of any bottled product. Exclude them; include one only if
  the label states no other risk text at all.
- Storage and handling instructions are likewise not risks.
- Return an empty list when the label genuinely does not state a field. Empty
  is a valid and common answer -- prefer it over a guess.

Output shape:
- purpose and risk are LISTS, one entry per distinct claim. A label stating
  "Promotes Energy Metabolism*" and "Supports Heart Health*" yields two
  purpose entries, not one joined string.
- Each entry has `evidence` -- characters copied from the label text above,
  unchanged, so the claim can be checked against the label -- and `text`, the
  same claim normalised: lowercased, trailing claim asterisk removed. Never
  write anything into `evidence` that is not in the text above.
- Where several distinct cautions share one block of label text and no
  substring isolates one of them, cite the block as `evidence` for each and
  put the individual caution in `text`.
- purpose_confidence and risk_confidence score 0-5 how clearly THE LABEL
  states that field -- 0 not at all, 5 explicitly and unambiguously. They
  score the clarity of the extraction, not how risky or effective the product
  is. Never judge a product's safety.

Worked example. Given this label text:

    PRODUCT: Huperzine A
    BRAND: GNC Herbal Plus Standardized
    TYPE: Botanical (Capsule)
    INGREDIENTS: Huperzine A

    LABEL STATEMENTS:
    [Precautions re: All Other] KEEP OUT OF REACH OF CHILDREN.
    [Precautions re: Pregnant or Nursing or Prescription Medications] WARNING: Do not exceed recommended intake. Consult your physicial prior to using this product if you are pregnant, nursing, taking medication, have high blood pressure, heart problems or have a medical condition. Discontinue use two weeks prior to surgery.
    [Storage] Store in a cool, dry place.
    [General Statements: All Other Content] Supports Memory Retention*
    [Suggested/Recommended/Usage/Directions] Directions: As a dietary supplement, take one to two capsules daily.

the correct extraction is:

    {
      "purpose": [
        {
          "text": "supports memory retention",
          "evidence": "Supports Memory Retention*"
        }
      ],
      "risk": [
        {
          "text": "do not exceed recommended intake",
          "evidence": "WARNING: Do not exceed recommended intake."
        },
        {
          "text": "consult your physician prior to using this product if you are pregnant, nursing, taking medication, have high blood pressure, heart problems or have a medical condition",
          "evidence": "Consult your physicial prior to using this product if you are pregnant, nursing, taking medication, have high blood pressure, heart problems or have a medical condition."
        },
        {
          "text": "discontinue use two weeks prior to surgery",
          "evidence": "Discontinue use two weeks prior to surgery."
        }
      ],
      "purpose_confidence": 5,
      "risk_confidence": 5
    }

Note, in that example:
- One WARNING block became three risk entries, because it states three
  distinct cautions. Each cites only its own sentence.
- KEEP OUT OF REACH OF CHILDREN was dropped: other risk text exists.
- Storage and Directions produced nothing.
- The label misspells "physicial". `evidence` keeps the misspelling because it
  is copied from the label; `text` reads "physician" because it is normalised.
  Correcting a typo inside `evidence` would make the claim uncheckable against
  the label, which is the one thing `evidence` exists to allow.
